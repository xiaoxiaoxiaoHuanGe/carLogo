# 自包含项目交接文档设计

## 目标

在项目根目录创建 `handoff.md`，使未来的自己或新的任务对话在没有当前聊天记录的情况下，仍能理解、构建、测试、发布并继续维护“猜车品牌”Android 应用。

## 受众与边界

- 受众是掌握基础 Android/Gradle/Git 操作的未来维护者。
- 文档以当前工作区和已发布 `v1.0.0` 为事实基线。
- 文档包含本机路径与命令，但不记录密码、密钥内容或令牌。

## 内容结构

1. 项目概述与当前发布状态。
2. 已完成能力、已修复问题和首发里程碑，至少五项。
3. 可执行的待办、优先级、预计工时和验收方式，至少三项。
4. 完整技术栈、明确版本、Android/Java/Gradle 环境要求及签名约定。
5. 关键源码、测试、设计文档、GitHub 仓库和 Release 的路径或链接。
6. 至少三项风险与注意事项，包括签名、版本递增、本地数据、题库维护和 IDE 文件。
7. 一个“新任务对话启动提示”，让接手者可直接将其作为上下文输入。

## 准确性规则

- 仅陈述已通过源码、Git 状态、构建输出或 Release API 验证的事实。
- 未实施的事项必须标为待办或建议，不得表述为已完成。
- `handoff.md` 可提交到仓库；密钥库、`keystore.properties`、`local.properties` 和构建产物保持忽略。
